# แผนทางเทคนิค: จองคิวตรวจสุขภาพ (Booking)

## 1. สรุปแนวทาง
ฟีเจอร์นี้ให้ผู้รับบริการที่ยืนยันตัวตนแล้วเลือกแพ็กเกจ วัน และช่วงเวลาตรวจสุขภาพ เพื่อจองคิวภายในวันเดียวกัน โดยระบบจะค้นหาช่วงเวลาว่างพร้อมจำนวนที่นั่งคงเหลือ จัดการการปฏิเสธเมื่อมีคิวที่ยังไม่ได้ใช้ และสร้างหมายเลขคิวเมื่อยืนยันสำเร็จ ส่วนข้อความยืนยันจะส่งแบบ asynchronous เพื่อให้การจองไม่หยุดรอ ผลิตภัณฑ์นี้มุ่งที่ฟังก์ชันหลักของ FR-BKG-01 ถึง FR-BKG-06 และต้องคงความสอดคล้องกับ AC-BKG-01 ถึง AC-BKG-06 โดยไม่รวมการยกเลิก/เลื่อนคิวหรือการจัดการโควตาเป็นฟีเจอร์ในสเปคนี้

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| MySQL | CON-TECH-01 | ใช้เก็บข้อมูลจอง ช่วงเวลา และ audit log ตามข้อจำกัดของฝ่าย IT |
| React + Vite | ทีมเลือกเอง ไม่ได้มาจาก spec | สำหรับหน้าเลือกแพ็กเกจ วัน และช่วงเวลา |
| Python FastAPI | ทีมเลือกเอง ไม่ได้มาจาก spec | สำหรับ API จองคิว ค้นหาช่วงว่าง และส่งคำขอแจ้งเตือน |
| ระบบยืนยันตัวตนที่มีอยู่แล้ว | IF-IDP-01 | ฟีเจอร์นี้ถือว่าผ่าน precondition แล้วก่อนเข้าถึงข้อมูลผู้รับบริการ |
| HIS lookup ด้วยเลขบัตรประชาชน -> map เป็น HN ภายในระบบ | IF-HIS-01 | ไม่เก็บเลขบัตรประชาชนในตารางจอง โดยใช้ HN เพื่ออ้างอิงภายในระบบ |
| ระบบแจ้งเตือน SMS/LINE แบบ asynchronous | IF-NOT-01 | การยืนยันการจองไม่รอผลส่งข้อความ |

## 3. โมเดลข้อมูล

### 3.1 Entity: Booking
| ฟิลด์หลัก | รายละเอียด | รองรับ ID |
|---|---|---|
| booking_id | รหัสการจองภายในระบบ | FR-BKG-04 |
| patient_ref | รหัสผู้รับบริการภายในระบบ (HN ภายในระบบ) | FR-BKG-02, FR-BKG-04, DOM-PDPA-01 |
| package_code | แพ็กเกจที่เลือก | FR-BKG-06 |
| booking_date | วันตรวจ | FR-BKG-01, FR-BKG-02 |
| slot_start | เวลาเริ่มช่วงเวลา | FR-BKG-01, FR-BKG-03 |
| slot_end | เวลาสิ้นสุดช่วงเวลา | FR-BKG-01 |
| queue_number | หมายเลขคิวที่ออกให้ | FR-BKG-04 |
| status | pending / confirmed / rejected / failed_notification | FR-BKG-02, FR-BKG-05 |
| created_at | เวลาเริ่มสร้าง | DOM-PDPA-01 |
| updated_at | เวลาอัปเดตล่าสุด | FR-BKG-05 |

### 3.2 Entity: SlotCapacity
| ฟิลด์หลัก | รายละเอียด | รองรับ ID |

| slot_start | เวลาเริ่ม | FR-BKG-01 |

### 3.3 Entity: AuditLog
| ฟิลด์หลัก | รายละเอียด | รองรับ ID |

## 4. API / หน้าจอ

### 4.1 หน้าจอ
- หน้าเลือกแพ็กเกจ: รองรับ FR-BKG-06
- หน้าเลือกวันที่และช่วงเวลา: รองรับ FR-BKG-01 และ FR-BKG-03
- หน้ายืนยันการจอง: รองรับ FR-BKG-04 และ FR-BKG-05
- หน้าแสดงหมายเลขคิวและสถานะข้อความยืนยัน: รองรับ FR-BKG-04 และ FR-BKG-05

### 4.2 API
- GET /api/slots?date_from=&date_to=&package_code= : คืนรายชื่อช่วงเวลาและจำนวนที่นั่งคงเหลือที่พร้อมใช้งาน; รองรับ FR-BKG-01 และ FR-BKG-06
- POST /api/bookings/validate : ตรวจว่าผู้รับบริการมีคิวที่ยังไม่ได้ใช้ในวันเดียวกันหรือไม่; รองรับ FR-BKG-02
- POST /api/bookings : สร้างรายการจองและออกหมายเลขคิว; รองรับ FR-BKG-04
- POST /api/bookings/{booking_id}/retry-notification : ส่งข้อความยืนยันซ้ำเป็นรายการคิว; รองรับ FR-BKG-05
- GET /api/bookings/{booking_id} : ดูสถานะและหมายเลขคิว; รองรับ FR-BKG-04, FR-BKG-05

## 5. ตารางตรวจ Constraints

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| CON-TECH-01 | ใช้ MySQL เป็น datastore หลักในโมเดลข้อมูลและการจัดเก็บ Booking / SlotCapacity / AuditLog | ใช้แล้ว |
| DOM-PDPA-01 | AuditLog และเงื่อนไขการบันทึกผู้เข้าถึง เวลา และรหัสผู้รับบริการภายในระบบ | ใช้แล้ว |
| IF-IDP-01 | Precondition ของรายการจอง: ผู้ใช้ต้องผ่านการยืนยันตัวตนก่อนเข้าถึงข้อมูลผู้รับบริการ | ใช้แล้ว |
| IF-HIS-01 | หาข้อมูลผู้รับบริการจาก HIS โดยใช้เลขบัตรประชาชนแล้ว map เป็น HN ภายในระบบ; ไม่เก็บเลขบัตรประชาชนในตารางจอง | ใช้แล้ว |
| IF-NOT-01 | ส่งข้อความยืนยันผ่าน SMS/LINE แบบ asynchronous และให้การจองไม่รอผล | ใช้แล้ว |

## 7. ลำดับงาน

1. สร้าง schema ฐานข้อมูลสำหรับ Booking, SlotCapacity และ AuditLog ตาม FR-BKG-01, FR-BKG-04, DOM-PDPA-01
2. สร้าง API ค้นหาช่วงเวลาว่างและคำนวณจำนวนที่นั่งคงเหลือตามแพ็กเกจ, รองรับ FR-BKG-01 และ FR-BKG-06
3. สร้าง logic ตรวจสิทธิ์ยืนยันตัวตนและ lookup HIS เพื่อ map เป็น HN ภายในระบบ, รองรับ IF-IDP-01 และ IF-HIS-01
4. สร้าง validation ป้องกันการจองซ้ำในวันเดียวกันและตรึงคิวเดิม, รองรับ FR-BKG-02 และ AC-BKG-02
5. สร้าง flow จัดการ slot full: แจ้งเตือนและแนะนำ 3 ตัวเลือกใกล้เคียง, รองรับ FR-BKG-03 และ AC-BKG-03
6. สร้าง flow ยืนยันการจอง: บันทึกการจอง, ตัดจำนวนที่นั่ง, ออกหมายเลขคิว, ส่งคำขอแจ้งเตือน, รองรับ FR-BKG-04 และ AC-BKG-01
7. สร้าง retry queue สำหรับข้อความยืนยันที่ไม่สำเร็จ และยืนยันคงบันทึกการจองแม้แจ้งเตือนล้มเหลว, รองรับ FR-BKG-05 และ AC-BKG-04
8. เพิ่ม audit log ทุกครั้งที่เข้าถึงข้อมูลผู้รับบริการ และตรวจสอบ log ตาม DOM-PDPA-01, AC-BKG-06
9. ทดสอบประสิทธิภาพและความปลอดภัยตาม NFR-PERF-01, NFR-SEC-01 และ NFR-USE-01
